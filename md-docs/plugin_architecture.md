# Архитектура плагинов

## Границы компонентов

`core` содержит доменные порты, репозитории, диспетчер событий и мост к VPN-движку. Он не читает нативные конфиги движков и не формирует протокольные ссылки.

- `engine_xray` владеет всем форматом Xray: чтением и записью JSON, шаблонами, Reality-ключами и проекцией конфигурации в `subscription_config_provider`.
- `subscription_runtime` получает нормализованный снимок и ссылки через контракты `pluginapi`; он не зависит от схемы Xray JSON.
- `traffic_file` владеет файловым накоплением трафика, квотами и отчётами `cli-stats`. Он публикует `traffic_provider`, `traffic_quota_provider` и `traffic_snapshot_provider`.
- `cluster_replication` использует только `traffic_snapshot_provider`, поэтому не импортирует файловое хранилище статистики и не знает, как получены счётчики.
- `subscription_autobalancer` обрабатывает шаблоны автобалансеров, а `subscription_format_legacy` экспортирует VLESS и Clash.

## Зависимости

Каждый плагин обязан объявить используемые сервисы в `Metadata.Requires`. Необязательная зависимость всё равно задаёт порядок инициализации, если её провайдер включён. Плагин должен корректно работать без необязательного провайдера или сообщать понятную ошибку только для отключённой возможности.

Публичные границы определяются только типами и именами из `internal/pluginapi`. Плагинам нельзя импортировать реализацию другого плагина ради доступа к данным или хранилищу.

## Проверка конфигурации

Для конкретного файла конфигурации порядок и доступные сервисы можно проверить командой:

```powershell
xraytool --config /etc/xraytool/config.yaml plugin graph
```

Перед развёртыванием выполняются:

```powershell
go test -count=1 ./...
go test -count=1 -tags minimal ./...
go vet ./...
```
