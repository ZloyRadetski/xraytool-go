# Документация Xraytool: API и Вебхуки

В этом документе описаны все существующие HTTP REST эндпоинты и вебхуки, реализованные на данный момент в бэкенде `xraytool`.

---

## 1. REST API Эндпоинты

Все эндпоинты по пути `/api/` (кроме публичных коллбеков) требуют передачи заголовка `X-API-Key` с мастер-ключом.

### 1.1. Подписки (Для клиентов)
Эти эндпоинты используются VPN-клиентами (V2RayNG, Shadowrocket и т.д.) для обновления профилей.

- `GET /client` - Легаси эндпоинт подписки.
- `GET /api/v1/sub` - Алиас для легаси эндпоинта.
- `GET /api/v2/sub` - Современный JSON эндпоинт. Поддерживает форматы VLESS и возвращает либо валидные профили подключения, либо конфигурации-заглушки (если превышен лимит, подписка истекла или пользователь заблокирован).

### 1.2. Управление Пользователями
Эндпоинты для регистрации пользователей, работы с балансом и настройками.

- `POST /api/v1/users/register`
  Регистрирует нового пользователя и генерирует для него профиль Xray.
- `GET /api/v1/users`
  Возвращает список всех зарегистрированных пользователей.
- `GET /api/v1/users/admins`
  Возвращает список пользователей с правами администратора.
- `GET /api/v1/users/telegram/{id}`
  Получить данные пользователя по его Telegram ID.
- `GET /api/v1/users/ref/{code}`
  Получить данные пользователя по реферальному коду.
- `POST /api/v1/users/telegram/{id}/balance`
  Изменить баланс пользователя (добавить или списать средства).
- `POST /api/v1/users/telegram/{id}/max-devices`
  Установить максимальное количество разрешенных устройств для пользователя.
- `POST /api/v1/users/telegram/{id}/auto-renew-toggle`
  Включить/выключить автопродление подписки для пользователя.
- `POST /api/v1/users/telegram/{id}/auto-renew`
  Запустить процесс автопродления вручную.
- `POST /api/v1/users/telegram/{id}/metadata`
  Установить или обновить произвольные JSON-метаданные пользователя.

### 1.3. Платежи
Эндпоинты для работы со счетами, балансом и интеграции с платежными системами.

- `POST /api/v1/payments/create`
  Создать новый платеж/счет в базе данных.
- `GET /api/v1/payments`
  Получить список всех платежей.
- `GET /api/v1/payments/{id}`
  Получить детальную информацию о конкретном платеже.
- `POST /api/v1/payments/{id}/status`
  Обновить статус платежа (например, pending -> completed).
- `POST /api/v1/payments/platega/callback`
  **[ПУБЛИЧНЫЙ]** Вебхук-эндпоинт для приема уведомлений об успешной оплате от платежного шлюза Platega.

### 1.4. Действия Администратора
Эндпоинты для ручного модерирования пользователей.

- `POST /api/v1/admin/users/{email}/block`
  Мгновенно блокирует пользователя (меняет статус на `blocked` и вырезает из конфигурации Xray менее чем за 0.01 сек).
- `POST /api/v1/admin/users/{email}/unblock`
  Разблокирует пользователя и возвращает ему доступ к VPN.
- `POST /api/v1/admin/users/{email}/set-expire`
  Ручное изменение даты окончания подписки (`ends_at`) для конкретного пользователя.

## 2. Вебхуки (События)

`xraytool` может отправлять `POST` запросы с JSON-данными на любые URL, указанные в файле `config.yaml` в блоке `webhooks`. Тело запроса содержит название события (`event`) и данные (`data`).

### 2.1. `subscription.expiring`
Срабатывает проактивно благодаря фоновому воркеру (Background Worker), когда подписка пользователя *скоро* закончится.
- **Триггер**: Настройки массива `worker.expiration_warnings` (например, за 24 часа до конца).
- **Данные в Payload**:
  - `email`: Email пользователя.
  - `time_left_sec`: Оставшееся количество секунд до полного окончания.
  - `warning_level`: Порог времени, который сработал (например, "24h").

### 2.2. `subscription.expired`
Срабатывает точно в тот момент, когда время подписки полностью вышло.
- **Триггер**: Фоновый воркер видит, что `ends_at` <= текущего времени.
- **Автоматические действия**: Пользователь удаляется из Xray, его статус в БД меняется на `expired`.
- **Данные в Payload**:
  - `email`: Email пользователя.
  - `sub_id`: ID подписки.

### 2.3. `payment.completed`
Срабатывает при переходе статуса платежа в `completed` (вручную через API или через коллбек от платежной системы).
- **Триггер**: Обновление статуса платежа.
- **Данные в Payload**:
  - `payment_id`: ID платежа.
  - `user_id`: ID пользователя, совершившего платеж.
  - `amount`: Сумма платежа.

### 2.4. `platega.callback`
Срабатывает всякий раз, когда платежный шлюз Platega присылает запрос на коллбек-эндпоинт. Полезно, если сторонний бот тоже хочет обрабатывать "сырые" данные от Platega.
- **Триггер**: Входящий запрос на `POST /api/v1/payments/platega/callback`.
- **Данные в Payload**: Сырой JSON, полученный от Platega.
